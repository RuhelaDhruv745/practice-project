# Reviewer dashboard (React)

React + TypeScript (strict) + Vite, Tailwind CSS, React Query, React Router.
A thin client of the FastAPI backend (`docs/API_CONTRACTS.md`): it shows what the API
returns and sends reviewer actions. It computes no segment, eligibility, amount, date or
validation result, and the backend is the only approval gate. The UI adds a visual
guard: approve is shown only for `pending_review` items with passing validation and a
`draft_allowed` decision, and a `409` from the API is shown as `error.code: message`.

## Run

```bash
cd frontend
npm ci
npm run dev            # http://localhost:5173
```

Configuration (Vite env vars, e.g. in `frontend/.env.local`, which is git-ignored):

| Variable | Default | Meaning |
|---|---|---|
| `VITE_API_BASE_URL` | `http://localhost:8000` | Backend base URL |
| `VITE_USE_MOCKS` | unset | `true` serves contract example responses from MSW (`src/mocks/`) instead of the API |

Against the real backend, start it with `CORS_ORIGINS=http://localhost:5173` so the
browser may call it.

## Pages

- `/` dashboard: review counts by status, customer counts by primary segment (API totals).
- `/customers`, `/customers/:id`: profile, evaluate (segments, reason codes with evidence,
  confidence, strategy, offer checks, verified facts incl. reminder stage, block reasons),
  generate draft.
- `/reviews`, `/reviews/:id`: queue (pending / blocked); detail with draft preview, edit
  (`PATCH`, re-validation result shown), validation findings (blocking highlighted),
  approve with optional 1-5 rubric, reject with required reason, reviewer history and
  audit trail.
- `/audit`: audit log filtered by customer, review or event type.

## API types

`src/types/api.ts` is generated by openapi-typescript; do not edit it by hand.

```bash
npm run gen:types                       # from ${VITE_API_BASE_URL}/openapi.json
npm run gen:types -- path/or/url.json   # from another schema source
```

Regenerate once the backend serves every endpoint.
